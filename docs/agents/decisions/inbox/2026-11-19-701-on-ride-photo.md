# On-ride photo: the default marker is 85% of the run, not of the lap (#701)

The issue asked for a default `photo` marker at "the lap's 85%". Every lap but the gym's is longer than a run
(level 1's is 147 s against a 60 s run, `ridePhysics.test.ts` `LAPS`), so 85% of the lap never comes round. The default is
where the ride is 85% of the way through the run (`photoMarker.ts` `photoDistance`, from the same `rideProfile` the spawner
plans with): late, before the end, on every level.

The gym's marker is in the Tree's gap as asked (`GYM_PHOTO_T`). On today's track the gap is the run's start, so its photo
is taken about 1 s after GO (the wall beside the rider, the Flame ahead); when the storyboard ride (docs/RIDE-KIT.md) ends at
the Tree, the marker moves with it.

The frame is taken with `createImageBitmap` on the WebGL canvas in an R3F after-effect (the drawing buffer still holds the
frame; no `preserveDrawingBuffer`, which would cost every frame). The snapshot waits for the frame's GPU work; the scaling
and the JPEG run in a Web Worker (`canvas/ridePhoto.worker.ts`, `OffscreenCanvas.convertToBlob`): done on the main
thread, CI's headless Chromium stalled the frame after the capture by 11–17 s. The smoke gates the capture's frame at 2x a frame without it (the frame before, or the
run's average), not a fixed ms, which on a software renderer would only measure the runner.
