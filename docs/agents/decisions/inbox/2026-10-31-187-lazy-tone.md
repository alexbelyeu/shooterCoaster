## 2026-10-31 — Tone.js loads on the first gesture, in its own chunk (builder, #187)

**Context:** Tone.js (~64 KB gz) sat in the main chunk although no sound can play before a user gesture.
**Decision:** `src/audio/tone.ts` owns it. The first gesture calls `initAudio()`, which creates and resumes the page's own
`AudioContext` synchronously in that handler (iOS Safari starts a context only there), then `import('./toneLib')` and hands
Tone that context with `setContext`. Main-chunk modules import Tone's types only and reach it through `tone()`, guarded by
`isAudioReady()`; the master chain is built after the load. `toneLib.ts` re-exports just the parts the main chunk uses, because
a dynamic `import('tone')` keeps the whole namespace (+16 KB gz). `vite.config.ts` `manualChunks.tone` holds Tone and `toneLib`.
Lazy chunks that only run after the unlock (score player, arcade SFX, offline render) still import `tone` statically.
**Consequences:** Startup JS 528 → 465 KB gz, total unchanged. A new Tone class used from the main chunk needs an export in
`toneLib.ts` (tsc says so). Anything that touches Tone before the first gesture must check `isAudioReady()` or it throws
into `soundGuard`. The smoke's title step fails if `tone-*.js` is fetched before the key press.
