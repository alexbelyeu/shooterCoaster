# ShooterCoaster — instructions for Claude

ShooterCoaster is a WebGL on-rails arcade shooter: you ride a rollercoaster through
themed biomes and shoot enemies against a timer. Owner: Alex Belyeu.

**This repo is developed autonomously by scheduled Claude sessions with no human
code review.** Alex reads a weekly report, watches the live `studio-status` issue
(generated by `scripts/studio-status.cjs`; never edit it by hand) and steers through
`docs/agents/STEERING.md` and GitHub issues labelled `steering`. Everything an
agent needs to know lives in this repo — sessions have no memory of each other.

If you were started by a scheduled task, run `scripts/pause-check.sh` first: if it
prints PAUSED, stop and reply with that line. Then read your runbook in
`docs/agents/runbooks/` and what it lists (normally `docs/agents/PROTOCOL.md` and your role
definition in `.claude/agents/`; the Builders and QA dispatchers read less) before doing
anything else.

```bash
npm run build             # typecheck (`tsc -b . scripts/new-world`: the game and the new-world templates; `npm run typecheck` alone) + production build -> dist/

npm run check:bundle      # bundle-size budgets (budgets.json): total, largest chunk, and the startup JS (what index.html loads, `startupJsGzipKB`)
npm run smoke             # headless playtest, the full run (the nightly's depth): title + every step on every level + the phone run (needs a build); `-- --shard <name>` runs one CI shard, the PR depth (e2e/shards.mjs)
npm run smoke:portal      # smoke the portal build served under /nested/path/ (the title and level1's ride, shot and results, ~5 min; CI `portal` job, only on PRs touching the portal's inputs (`vite.config.ts`, `index.html`, `public/`, `scripts/portal/`, `package*.json`, `ci.yml`) and nightly on main, which then keeps the zip as the 30-day artifact `dist-portal`; needs build:portal)

npm run lighthouse        # Lighthouse on dist/ (vite preview), mobile + desktop: fails below SEO 100, Accessibility / Best Practices 95; Performance printed only (needs a build + SC_CHROME; e2e-results/lighthouse.json; docs/marketing/SEO.md)
npm run verify            # test + lint + build + bundle budget + lighthouse + the full smoke; agents don't run it before pushing (builder.md step 7: test + lint + build + check:bundle + a narrow smoke) (CI's gate on every PR is its PR depth: parallel jobs, `unit + build`, `lighthouse`, one `smoke (<shard>)` each and a `pacing (<level>)` per level the PR can change (#761), then the required `verify` gate; a first `changes` job plans the run with `scripts/ciPlan.cjs`: a docs-only PR (`isDocsOnly`) skips the smoke and Lighthouse, and `unit + build` unless it touched `scripts/`, and still gets a green `verify`; e2e/README.md)
bash scripts/quiet.sh <cmd>    # run any noisy command with its output in a log file: prints status (+ failures and tail on error)
npm run og                # re-render the share card public/social/og-1200x630.jpg (a level-1 frame under the title logo) and the title posters public/poster/*.webp (needs a build) + the icons from public/favicon.svg (favicon.ico, apple-touch-icon, manifest icons/; `-- --icons` for just those, no build; `-- --poster` for just the posters, `-- --card` for just the share card)
npm run clip              # render the level-1 gameplay clip (MP4 + stills) to docs/marketing/media/ in virtual time, the GIF to e2e-results/clip/ (needs a build + ffmpeg, ~15 min; `-- --level <id>` for another level; the vertical cut: `-- --size 720x1280 --ride-only --seconds 16.4`; the title alone: `-- --title --seconds 9` (`--attract` for attract mode); the level's intro tour before its ride: `-- --tour --from 0`; a quick review clip of one stretch, no menus: `-- --level level6 --from 0.13 --seconds 6 --direct --quality low`; re-render policy in docs/marketing/media/README.md)
npm run new-world -- <levelId> --name "<Name>" --biome <biome> [--interior] [--score-from <levelId>] [--dry-run]   # scaffold a new world (#460): biome files and registry entries from the templates in scripts/new-world/ (real TS, typechecked and linted; the plan is pure in scripts/newWorldPlan.mjs), its music score copied from `--score-from` (default level1), the level (a starter roster), every registration and gate (scene / pacing budgets as placeholders the first local smoke fills), then prints what is left by hand (docs/LEVEL-KIT.md); refuses an existing id
npm run turntable         # enemy turntable (#380): every enemy + boss up close under studio light -> e2e-results/turntable/ sheet.png, <id>-angles.png (front / side / back / 3/4), <id>-motion.png (4 frames over a cycle), results.json; builds dist-turntable/ (`-- --skip-build`, `--only crow,kraken`, `--biome ocean`); the page is turntable.html (`npm run dev` serves it: `?enemy=<id>`, `&animate=1`, `?yaw=`, `?biome=`), never in the game's build; CI's `turntable` workflow uploads it on PRs touching src/entities/** or death styles; `-- --rides` renders the ride elements strip instead (#698: `rides.png`, the demo circuit's loop, zero-g roll, corkscrew… from the seat and a shot hit upside down, then the special mechanics' circuit (#699): station launch, jump gap, drop track, backwards and a shot hit facing back; the page is rides.html, `src/dev/rides/`)
npm run audio:render -- --music <title|level1..5> | --sfx-sheet [--level id] | --mix <level> [--boss] | --ride <level> | --launch <level> | --resume <level> [--unpaused]   # offline render of the game's sound → docs/audio/renders/<name>.{mp3,json,png} (needs a build + ffmpeg, ~20 s); (--music also takes results and a theme option `<slot>.<name>`; `--seam` starts 10 s before the loop seam; `--layers 0..3|ramp` plays the score's intensity layers); a --mix also renders its music alone to measure each kill against (and its seams on); `--boss` adds the boss's arrival and defeat, the score's boss section and sting, 30 s; `--ride` is the ride's own sounds (GO's launch whoosh, a chain lift, the drop's wind and rail rumble to top speed); `--launch` is level select's launch blip with the level's bank and room landing under it, checked for a click at the swap; `--resume` is a paused run's resume Ready / GO with the pause gate opening at GO (`--unpaused`: the same without the pause, which it should match)

npm run audio:check -- <file.wav|mp3> [--kind music|mix|sfx] [--seam s] [--click s] [--music stem.wav] [--strict]  # loudness, true peak, clipping, bands, seams, clicks at a cut, gun tail, kill over music vs the sound bible's targets
```

Unit tests live next to the code as `src/**/*.test.ts` (and `scripts/**/*.test.ts` / `e2e/**/*.test.ts` for agent tooling and the smoke) and run in plain Node
(`vitest.config.ts`): no DOM, no WebGL. A test may call `expect()` at most 50 000 times (`scripts/vitestAssertionBudget.ts`: assert once after a sampling loop, not inside it). Test pure logic (track curves, terrain
noise, scoring/stars in `src/levels/scoring.ts`, store actions, level configs);
keep pure helpers free of React/three imports so they stay testable. Adding a
level? `src/levels/LevelRegistry.test.ts` checks its `maxScore`, star thresholds
and `nextLevel` chain, and the curve/terrain tests sample its track automatically;
the smoke fails it until it has a `scene` entry in `budgets.json` (perf gate below).

Headless browser in Claude cloud sessions: the Playwright CDN is blocked, so run
`export SC_CHROME="$(scripts/ensure-browser.sh)"` once per session before `npm run smoke`.
The smoke test writes PNG screenshots + `results.json` (frames, draw calls, triangles,
avg frame ms, kills, score, combat stats, on-screen enemies, errors) to `e2e-results/`:
`title.png` (and `title-attract.png`, attract mode), then per level `<id>.png` (the ride), `<id>-enemy.png`, `<id>-combat.png`,
`<id>-shot.png`, `<id>-results.png`, plus step shots (`level1-boss.png`, `level2-wave.png`, …)
and `mobile-*.png` with `--mobile`. Each level prints one summary line; a level fails on
blank or stalled rendering, unreadable enemies, missing kills or effects, page errors, or
the **perf gate** (`budgets.json` `scene` ceilings; only the Director raises them).
The smoke has two depths (#372). On a PR, CI runs the rendering and integration checks as parallel shards
(`e2e/shards.mjs`: the UI steps, the ride and combat on every level, level1's frozen shot, results screen, quality
and speed, the phone run's touch play), each under a `smokeSeconds` budget in `budgets.json` (over it is a warning; on CI the shard
fails only past 1.5x it: `level3 shard took 11.0 min, budget 7.0, fails past 10.5`; a level shard's budget is scaled up, at most 2x, on a runner whose ride rendered
slower than a normal one's, `e2e/shardTime.mjs`). The deep checks (full boss fights, waves, FRENZY end, initials entry,
share, daily, pause, countdown, pickups, scrim, the phone menus, and `pacing`: every level's whole run, failing a level whose
time with nothing to shoot is over its `budgets.json` `pacing` ceilings, `e2e-results/pacing.json`; game logic among them has unit tests next to its
pure module) run in the full smoke, nightly on production (`prod-smoke.yml`, as three parallel parts, `--nightly-part <main|deep|pacing>`; a red one opens `agent:prod-broken`).
Every level's ride and `pacing` line ends with `programs after warm-up: +N` (shaders `ShaderWarmup` missed, with the moment
each appeared; reported, not failed, #536), and `--cpu-throttle 4` runs the ride under CDP CPU throttling, adding the longest
frame and the frames over 100 ms per level; `--level-chunk-delay <ms>` serves the lazy level chunk that late (every step waits for `levelReady()`, #464). A red `smoke (<shard>)` check names the shard: reproduce it with
`node e2e/smoke.mjs --shard <name>`, a nightly failure with its step (`--steps` / `--levels` pick any subset); its screenshots are the run's
`e2e-results-<shard>` artifact. A new level needs a shard and a budget (`e2e/shards.test.ts` fails until then).
`drawCalls`/`triangles` vary with the camera: compare levels with the `scene` totals the
smoke prints. **The full list of what each step checks, its flags and the test hook
(`?e2e=1` → `window.__SC_TEST__`, the API the smoke and `npm run clip` drive) is in
`e2e/README.md`**: read it before changing `e2e/`, `src/testing/e2eHook.tsx` or anything a
smoke step checks, or when a failure needs more than its summary line.

## Stack

React 19 + @react-three/fiber 9 + drei + @react-three/postprocessing, three 0.172,
Web Audio (procedural music and SFX, no audio library), zustand (state),
framer-motion (UI), Vite 6, TypeScript strict. Fonts (Ultra, Big Shoulders; Lobster for the logo; Inter until every screen has moved to the personality below) are self-hosted from `public/fonts/` (OFL, Ultra Apache 2.0); the game makes no
third-party request at runtime. `vite build --mode portal` (`build:portal`) is the same game with `base: './'` for web portals. Deployed on Vercel: every push to
`main` goes to production at **https://scoaster.com** (www.scoaster.com redirects there; https://shooter-coaster.vercel.app also still serves it). Preview deployments
are disabled (`git.deploymentEnabled` in `vercel.json`) — verification happens in CI. `vercel.json` rewrites only
the `/go/<campaign>` landing paths to the game; any other unknown path gets `public/404.html` with a real 404,
and it sets the security headers and a year's `immutable` cache on Vite's hashed `/assets/*` (so nothing unhashed goes in
`public/assets/`); `scripts/vercelRoutes.mjs` models the routing and headers, which `scripts/site.test.ts` checks (with the share card, manifest and icons) and `e2e/prod-check.mjs` holds the live site to. `index.html` carries
the SEO head (meta, share card, `site.webmanifest`, `["VideoGame", "WebApplication"]` JSON-LD; the checklist and its sources are `docs/marketing/SEO.md`) and a visually hidden `#about` section
(outside `#root`, so it survives React's mount) that crawlers and screen readers read (the portal build drops the share-card tags, the manifest and the JSON-LD, keeps `#about`);
`src/app/indexHtml.test.ts` checks the JSON-LD, the one `h1`, that it names every level and that the poster's logo is `TitleLogo`'s still markup. Before any JS, `index.html` paints the **poster** (#376): `#poster`, the title scene's still (`public/poster/title-{landscape,portrait}.webp`, from `npm run og`) under the title's logo (inline SVG) and a PLAY placeholder, its fonts and still preloaded; it sits over the canvas and under the UI, the title screen lays its logo exactly over the poster's (`src/app/poster.ts` `handPosterToUi`), and `GameCanvas` fades it out once the canvas has drawn two frames and the level chunk has arrived (at most 2.5 s more; its evaluation is one long task, kept under the poster, #597) (`dismissPoster`). The title step of the smoke checks it with JS off (`poster.png`) and shoots the cold load until the live scene shows: no blank frame. Scores and the Daily Run are saved in the browser; the one
backend is the **online leaderboard** (#365): `api/leaderboard.ts`, a Vercel Function, keeps the campaign's top 10 per level in Alex's own Supabase project
(`SUPABASE_URL` + `SUPABASE_SECRET_KEY`, Production env vars he sets; setup, restore and the table in `docs/LEADERBOARD.md`). Only scoaster.com's own build calls it
(never dev, `vite preview`, CI, the portal build or `?e2e=1`); without the env vars, a paused project or any error it answers 503 and the game keeps the local board.
**Player telemetry** (#373, `docs/TELEMETRY.md`): `src/telemetry/` sends one `sendBeacon` per page load to `api/telemetry.ts` (same Supabase project, table
`telemetry_reports`) when the tab is first hidden: deduped errors, WebGL context losses, per-level median / p95 frame ms with quality and dpr, device class;
no ids. It shares the Web Analytics gate below. `GET /api/telemetry` is the last 24 h aggregated, which the status page and the watchdog read (`scripts/playerTelemetry.cjs`).
Vercel Web Analytics (`@vercel/analytics`: page views, plus the `level_start` /
`level_complete` / `level_quit` custom events mapped from game-store phase changes in
`src/app/analyticsEvents.ts`, plus `share` (with its `method`) from the results screen's Share button via the `results:shared` bus event, listed in `docs/marketing/README.md`) is mounted in `src/main.tsx`
only on Vercel builds (`__BUILT_ON_VERCEL__`, set in `vite.config.ts` from `VERCEL=1`)
and never with `?e2e=1` (`src/app/analyticsGate.ts`), so dev, `vite preview`, CI and the
smoke tests send nothing. `?internal=1` marks a browser internal (localStorage flag, stripped
from the URL; `?internal=0` clears it, any other value is ignored; the title's Settings has the same flag as an "Internal device" toggle, from the next load): it sends nothing either, via the same gate and a
`beforeSend` that drops every page view and event while the flag is set. `applyInternalParam` decides once per page
load and the title's "Internal device, not tracked" marker reads that decision (`isInternalThisLoad`), so it shows even when
storage can't be written. Campaign links use landing paths `/go/<campaign>` (the catch-all rewrite serves the game there;
never redirect them, the page view's path is the attribution).

## Context budget (all agents)

Everything you read stays in your context and is paid for again on every later turn
(cache writes were half of all studio spend in late Oct 2026; the token ledger now logs
each run's peak context, compactions, cache misses, heaviest tool results and, for a run with
subagents, weighted tokens / turns / peak context per agent).

- This file is already in your context: don't Read it again.
- Run noisy commands through `bash scripts/quiet.sh` (`npm ci`, `npm test`, `npm run build`,
  smoke, `verify`, lighthouse, `audio:render`): it keeps the full log on disk and prints a
  status line, plus the failures and tail when it fails. `grep -n` / `sed -n` the log for more.
- Don't `cat` large files, logs or `results.json`: `grep -n` first, then Read with
  offset/limit; `jq` only the fields you need from JSON.
- Look only at the screenshots that answer your question (usually one or two), not every PNG.
- Don't poll or `sleep` waiting for CI, merges or a backgrounded smoke: a gap of over
  ~5 minutes between turns expires the prompt cache, and the next turn pays for the whole
  context again. Run long commands in the foreground through `quiet.sh`, capped under the cache's
  5 minutes (`bash scripts/quiet.sh timeout 270 …`: a longer command is the same idle gap); don't wait for CI at all.
  The watchdog files any run over 5M weighted tokens as a `studio-health` issue.

## Hard rules (all agents, always)

1. `main` must always build, pass CI's `verify` (the PR-depth smoke shards, unit + build, Lighthouse), and be playable. Never merge red.
   The full smoke runs nightly on production (`prod-smoke.yml`); a red one opens `agent:prod-broken` and is P1.
2. Never force-push, rewrite history, or push directly to `main`. All changes go through PRs. Agents never merge: approval is the `agent:qa-approved` label and GitHub auto-merges (see PROTOCOL.md).
3. Never delete or disable an existing level, mode or feature without a playable replacement in the same PR.
4. No new paid services, accounts, API keys or secrets. No secrets in code. No new third-party network calls at runtime without a DECISIONS.md entry.
5. Only add assets you created (procedural / code-generated) or that are explicitly CC0, and record source + licence in `docs/ASSETS.md`.
6. Budgets in `budgets.json` are enforced by CI. Only the Director may raise them, with a DECISIONS.md entry.
7. Large rewrites (engine, renderer, state, physics) land behind a feature flag or in parallel modules until they reach parity — never a big-bang swap.
8. Dispose three.js geometries/materials/textures and disconnect Web Audio nodes you create; no allocations in per-frame hot paths. See `docs/HEAP-BOTTLENECKS.md`.
   Lint enforces it: `sc/no-hot-path-alloc` (`scripts/eslint/no-hot-path-alloc.mjs`) fails an allocation inside a `useFrame` callback or any function of a `*.hot.ts` module (the per-frame helpers they call); a cold line is allow-listed with `// eslint-disable-next-line sc/no-hot-path-alloc -- <why>`.
9. Keep this file and `docs/CODEMAP.md` accurate. If you change commands, structure or rules, update them in the same PR.
10. Never create, fire, update or delete scheduled tasks or reminders, and never call the studio
   control center (`control.scoaster.com`, repo `alexbelyeu/studio-control`, Alex's console that starts runs): no safety-net check-ins, no `send_later`, `create_trigger`, `fire_trigger`, `update_trigger` or `delete_trigger`, even if a default habit suggests re-checking a PR later. Follow-up on every PR is already automatic: QA (on label) reviews it, Fix (on label) fixes what QA sends back, and the Maintainer sweeps anything stuck each night. End your session when your runbook's work is done. Only Alex, or his own interactive Claude session, manages scheduled tasks.

"A DECISIONS.md entry" means a **new file** in `docs/agents/decisions/inbox/` (format in its README). Never edit `docs/agents/DECISIONS.md` directly: the Maintainer folds the inbox into it nightly, which keeps parallel PRs from conflicting.
