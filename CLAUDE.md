# ShooterCoaster — instructions for Claude

ShooterCoaster is a WebGL on-rails arcade shooter: you ride a rollercoaster through
themed biomes and shoot enemies against a timer. Owner: Alex Belyeu.

**This repo is developed autonomously by scheduled Claude sessions with no human
code review.** Alex reads a weekly report, watches the live `studio-status` issue
(generated by `scripts/studio-status.cjs`; never edit it by hand) and steers through
`docs/agents/STEERING.md` and GitHub issues labelled `steering`. Everything an
agent needs to know lives in this repo — sessions have no memory of each other.

If you were started by a scheduled task, run `scripts/pause-check.sh` first: if it
prints PAUSED, stop and reply with that line. Then read your runbook in
`docs/agents/runbooks/` and what it lists (normally `docs/agents/PROTOCOL.md` and your role
definition in `.claude/agents/`; the Builders and QA dispatchers read less) before doing
anything else.

## Commands

```bash
npm ci                    # install
npm run dev               # dev server (vite)
npm test                  # vitest unit tests for pure modules (~1s; `npm run test:watch` to iterate)
npm run build             # typecheck (tsc -b) + production build -> dist/
npm run check:bundle      # bundle-size budget (budgets.json)
npm run smoke             # headless playtest: title + every level + phone touch run (needs a build)
npm run verify            # test + build + bundle budget + smoke — run before every PR
npm run og                # re-render the share card public/social/og-1200x630.jpg + apple-touch-icon (needs a build)
npm run clip              # render the level-1 gameplay clip (MP4 + GIF + stills) to docs/marketing/media/ in virtual time (needs a build + ffmpeg, ~15 min)
```

Unit tests live next to the code as `src/**/*.test.ts` (and `scripts/**/*.test.ts` for agent tooling) and run in plain Node
(`vitest.config.ts`): no DOM, no WebGL. Test pure logic (track curves, terrain
noise, scoring/stars in `src/levels/scoring.ts`, store actions, level configs);
keep pure helpers free of React/three imports so they stay testable. Adding a
level? `src/levels/LevelRegistry.test.ts` checks its `maxScore`, star thresholds
and `nextLevel` chain, and the curve/terrain tests sample its track automatically.

Headless browser in Claude cloud sessions: the Playwright CDN is blocked, so run
`export SC_CHROME="$(scripts/ensure-browser.sh)"` once per session before `npm run smoke`.
The smoke test writes PNG screenshots + `results.json` (frames, draw calls,
triangles, avg frame ms, kills, score, combat stats, on-screen enemy counts/sizes, errors)
to `e2e-results/`: `title.png` and `title-2.png` 6 s later (the fly-by camera must have turned ≥ 8° or moved ≥ 30 units;
the start hint must show and a key press must fade to black and open level select), and per level `<id>.png` (after a ride of `--seconds` 10, longer until `--min-frames` 10 frames have rendered; it fails as a stalled render loop only if they haven't by 4× `--seconds`, and the summary line prints `frames=N in Xs`; the title waits the same way),
`<id>-enemy.png` (4× close-up of the largest on-screen enemy, time frozen), `<id>-combat.png`
(after 4 s of autofire + `killNearest(5)`, with the weapon's muzzle flash + tracer and the
gold hitmarker held on the kill frame via `holdFeedback`; on the first level a primed 14-kill chain makes
that kill enter the 5× combo tier, and the shot must show the "×5 FRENZY" flash with its slow-mo held), `<id>-shot.png` (one real shot two 40 ms
steps into its flight, time frozen) and `<id>-results.png`. A level fails if
fewer than 2 enemies are ≥ 12 px on screen right after the ride (`enemiesOnScreen` / `readable` / `largestPx` in the summary), it gets no kills, a real mouse click doesn't fire, autofire never fires at on-screen
enemies, the `killNearest` hits never produce an `enemy:killed` (skipped if the
wall-clock level timer already ran out), the camera translates off the track pose at all
(kill feedback is rotation-only trauma, ≤ 1°, back to 0), the first-person weapon is off
screen / covers the centre / overlaps the HUD / points > 25° off the tracer of the frozen fixed-point shot (also
checked in mobile portrait + landscape),
the camera aspect doesn't match the canvas (±0.01), any drawn bullet's screen radius exceeds 2% of the
canvas height (also checked on the phone run), a fresh shot isn't drawn at the muzzle tip, or the results screen never finishes its
reveal (`data-sequence="done"`), lacks a stats row (kills, accuracy, best combo, time left) or the
Levels / Replay buttons, shows NaN, or disagrees with `stats()` on score or kills.
`npm run smoke` also passes `--mobile`:
an iPhone 13-like touch context (390x844) taps PLAY and a level (the title music must ramp out from full and be disposed, the level music ramp in), then in portrait and
again in 844x390 landscape taps the canvas 10x, each tap 15–30 px off an on-screen
enemy (game time frozen while tapping), and requires kills (touch aim assist); checks
camera aspect == canvas aspect in portrait, landscape and after rotating back, that the
HUD is inside the viewport with no overlap in both orientations, that the SFX node count doesn't grow across the taps and the music ducks while time is frozen, runs the `audioBurst` Tone scheduling stress in portrait and after rotating (every desktop level runs it too: any page error, late note that throws or dropped sound fails), and taps Pause (`mobile-level-select.png`, `mobile-level1.png`,
`mobile-level1-landscape.png`; `--skip-desktop` runs only that). **Look at the screenshots** with the Read tool — that is how you
playtest visually. Waits are polled against the frame counter because software
rendering can run at ~1 fps; tune with `--seconds`, `--combat-seconds`,
`--min-frames`, `--levels level1,level3`, `--shot-timeout <ms>` (default 120 s),
`--seed <n>` (default 1337). Every smoke run pins that run seed, so enemy spawns are the
same each time; a `seed-check` step reloads the first level and requires the same
`spawnDigest()` for the same seed and a different one for another seed. A `hidden-pause`
step fakes a tab hide (`visibilitychange`) on the first level: the run must pause, drop a
held trigger, keep `timeRemaining` still over 5 s hidden, stay paused when shown again, and
after Resume neither reset nor jump the timer, and a combo primed before hiding must survive the pause;
a window `blur` must pause too.
A `levelSelect` step seeds saved progress (3★ + 1★), opens the level select (`levelSelect.png`)
and requires one card per level, the right locked count and `★ x / 15` total, every card
inside 1280×720 with no sideways scroll, and keyboard-only play (arrows move focus, Enter on a
locked card does nothing, Enter on an open one plays the launch transition and starts that level);
the phone run checks its cards fit 390 px.
`?e2e=1` skips the Ready / Set / GO countdown (runs start in `playing`); a `countdown` step
loads the first level with `?e2e=1&countdown=1`: the countdown must show (`countdown.png`),
a press during it must fire nothing (also when held on into `playing`), the timer must hold, a replay tap after 1 s skips to `playing`,
and the shader warm-up must finish; after it, the first shot + kill must compile no new shader program
(`programs()`; the longest frame is reported). A `speed` step holds the first level at top speed on the most
banked of ten sampled track points: the wind streaks must show and the camera must bank ≥ 1° (`speed.png`).
When level2 is in the run, a `wave` step rides it to the crow wave: its `wave:incoming` tell (screen-edge pulse +
label) must come before the wave, then the V flies in and is frozen for `level2-wave.png` (≥ 5 crows on screen, none within 40 units).
`drawCalls`/`triangles` depend on where the camera happens to be (frustum culling,
spawned enemies) and vary run to run; for before/after comparisons use the
camera-independent `scene` totals the smoke also prints (`track objs/tris` = objects
named `track*`; `env=` is the baked sky env map's intensity and bake time; a level
without `scene.environment` fails).

Test hook: load the game with `?e2e=1` and use `window.__SC_TEST__`
(`levels()`, `startLevel(id, seed?)`, `primeCombo(n)` (live chain of n kills, last one now), `setPhase(phase)`, `setSavedScores(scores)`, `spawnDigest()` → hash of the run's spawn positions (formation members: their seeded slots), `waveEvents` (every `wave:incoming` / `wave:announce` with its time), `frames`, `drawCalls`, `triangles`, `avgFrameMs`, `maxFrameMs` (longest frame since a test set it to 0), `programs()` (compiled shader programs), `cameraPose()` (position + view direction),
`errors`, `phase()`, `enemies()` → on-screen enemies with projected px, `stats()` → score/kills/combo/multiplier/timeScale/frenzy/timeRemaining/phase/liveEnemies/
onScreenEnemies/shotsFired/hits/bestCombo/runSeed/currentLevel, `autoFire(on)`, `killNearest(n)` (fires one real shot,
then resolves hits via `processHit`, the bullet pool's own path), `enemyScreenPoints(n)`,
`fireShot(x, y)` (one real shot through NDC), `bullets()` → drawn count, largest screen radius now / since load, newest bullet's
screen point, `bulletStep` (seconds per frame for every live bullet; 0 freezes them), `endLevel()`, `setTimeScale(s)`, `rideTo` (set a track fraction 0–1 to jump the coaster there), `rideSpeed` (set 0–1 to put the coaster at that speed), `sceneStats()`, `combat` fire/hit/kill event counters,
`cameraTranslation` {current, max} = translation off the track pose (must be 0), `cameraTrauma`
{current, max} in degrees, `cameraWeight` → bank / pitch / speed + drop FOV kick now and max (degrees), smoothed speed 0–1, wind-streak opacity, `weapon` → the gun's on-screen box, pivot, muzzle tip + last shot point, `holdFeedback`,
`view()` → camera vs canvas aspect + FOV, drawing-buffer size + dpr, `audio()` → unlocked?, live SFX node count, music ducked?, sounds dropped by a caught audio error, `music` (live music buses with their gain + the last few fade ramps),
`audioBurst(shots, kills)` → rapid SFX + late music notes in one JS turn while the audio clock ticks, `triggerHeld()` → pointer trigger down?,
`shaderWarmup` {done, ms, programs} for the current level). See `src/testing/e2eHook.tsx`. Extend it when you need new test
surfaces. Bullets travel per *second* with a swept hit test (`combat/projectiles/bulletMotion.ts`) along the camera ray;
they are *drawn* from the gun's muzzle into that ray, capped to 1.5% of the canvas height on screen (`bulletVisual.ts`),
but enemies and the camera still move a lot during one ~1 fps headless frame, so
autofire only sometimes lands hits — `killNearest` is what guarantees kills.
The coaster camera sets its own aspect/FOV from the canvas size (`track/cameraFov.ts`:
portrait screens get a wider vertical FOV, plus a few degrees with speed and on steep drops) and has rotation-only
weight (`track/cameraRig.ts`: look-ahead into curves, bank into turns, pitch with speed changes;
bank, pitch and the FOV kick scale with the Screen-shake setting, and the smoke fails past their caps).
Above ~70% of top speed, camera-space wind streaks fade in (`track/WindStreaks.tsx`, numbers in `windStreaks.ts`;
one draw call, hidden when slow, also scaled by Screen shake); touch shots get aim assist (`combat/aimAssist.ts`).
`npm run clip` drives the same hook in virtual time (`scripts/clip.mjs`: Playwright's fake clock plus a page
`requestAnimationFrame` that runs only when the script asks), so each captured frame is exactly 1/30 s of
game time for every consumer (R3F, timers, framer-motion) however slowly software GL draws it; no game code is involved.

## Stack

React 19 + @react-three/fiber 9 + drei + @react-three/postprocessing, three 0.172,
Tone.js (procedural audio), zustand (state),
framer-motion (UI), Vite 6, TypeScript strict. Deployed on Vercel: every push to
`main` goes to production at **https://scoaster.com** (www.scoaster.com redirects there; https://shooter-coaster.vercel.app also still serves it). Preview deployments
are disabled (`git.deploymentEnabled` in `vercel.json`) — verification happens in CI. Serverless stubs in `api/` (leaderboard, daily seed, ghost
replays — currently in-memory placeholders).
Vercel Web Analytics (`@vercel/analytics`: page views, plus the `level_start` /
`level_complete` / `level_quit` custom events mapped from game-store phase changes in
`src/app/analyticsEvents.ts`, listed in `docs/marketing/README.md`) is mounted in `src/main.tsx`
only on Vercel builds (`__BUILT_ON_VERCEL__`, set in `vite.config.ts` from `VERCEL=1`)
and never with `?e2e=1` (`src/app/analyticsGate.ts`), so dev, `vite preview`, CI and the
smoke tests send nothing. `?internal=1` marks a browser internal (localStorage flag, stripped
from the URL; `?internal=0` clears it): it sends nothing either, via the same gate and a
`beforeSend` that drops every page view and event while the flag is set.

## Skills in this repo

`.claude/skills/` has project knowledge — use it:
- `shooter-coaster-level-design` — **read before touching levels, enemies, decorations, terrain or landmarks.** It encodes hard-won rules (track extent formula, enemy scaling, z-fighting, terrain-following).
- `threejs-*` — three.js reference for materials, shaders, lighting, postprocessing, etc.
- `workflow-orchestration` — plan → execute → verify discipline.
- `branch-review` — the architecture/convention rubric the `pr-consistency` reviewer applies.

Commands: `/deslop` (`.claude/commands/deslop.md`) cuts AI slop from the files a branch
touches; builders run it before shipping. `/wrap-pr` runs the two independent reviewers
on a PR; QA runs it on every sizeable PR.

## Hard rules (all agents, always)

1. `main` must always build, pass `npm run verify`, and be playable. Never merge red.
2. Never force-push, rewrite history, or push directly to `main`. All changes go through PRs. Agents never merge: approval is the `agent:qa-approved` label and GitHub auto-merges (see PROTOCOL.md).
3. Never delete or disable an existing level, mode or feature without a playable replacement in the same PR.
4. No new paid services, accounts, API keys or secrets. No secrets in code. No new third-party network calls at runtime without a DECISIONS.md entry.
5. Only add assets you created (procedural / code-generated) or that are explicitly CC0, and record source + licence in `docs/ASSETS.md`.
6. Budgets in `budgets.json` are enforced by CI. Only the Director may raise them, with a DECISIONS.md entry.
7. Large rewrites (engine, renderer, state, physics) land behind a feature flag or in parallel modules until they reach parity — never a big-bang swap.
8. Dispose three.js geometries/materials/textures and Tone.js nodes you create; no allocations in per-frame hot paths. See `docs/HEAP-BOTTLENECKS.md`.
9. Keep this file accurate. If you change commands, structure or rules, update CLAUDE.md in the same PR.
10. Never create, fire, update or delete scheduled tasks or reminders: no safety-net check-ins, no `send_later`, `create_trigger`, `fire_trigger`, `update_trigger` or `delete_trigger`, even if a default habit suggests re-checking a PR later. Follow-up on every PR is already automatic: QA (on label) reviews it, Fix (on label) fixes what QA sends back, and the Maintainer sweeps anything stuck each night. End your session when your runbook's work is done. Only Alex, or his own interactive Claude session, manages scheduled tasks.

"A DECISIONS.md entry" means a **new file** in `docs/agents/decisions/inbox/` (format in its README). Never edit `docs/agents/DECISIONS.md` directly: the Maintainer folds the inbox into it nightly, which keeps parallel PRs from conflicting.
